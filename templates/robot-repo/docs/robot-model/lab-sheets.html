P1. Season setup

Design leads + programmer · once per robot · ~1 hour

In Onshape (main assembly)

  • Configuration input Export = Full / AdvantageScope. In AdvantageScope, suppress game pieces, wiring, chain, belts, cosmetic parts. Hidden parts still export.
  • Mate connector ascope_origin on the drivetrain: center of frame, floor plane, +X front, +Z up.
  • Only one Fixed part, on the drivetrain. Every other part is mated (Fastened is fine).
  • Each moving mechanism: one Revolute or Slider mate named j_lowercase_name, unique, with limits. No Planar, Cylindrical, Parallel or Ball.
  • Closed loops (four-bars): fasten all but one joint in AdvantageScope.
  • Stages driven by one motor: link the Sliders with a linear relation.
  • Cameras: connector cam_NAME at the lens center (+X out of the lens, +Z up). Measured points: frame_name.
  • Pose every j_ mate at code zero, save Named Position ascope_zero, create a Version.

On a team laptop (needs uv)

  1. Export: right-click assembly tab → Export → URDF, GLTF, Medium, rigid subassemblies off.
  2. uvx --from git+https://github.com/FRC1076/cad2ascope cad2ascope inspect export.zip: every j_ mate says MOVES; fix any Notes.
  3. … cad2ascope init export.zip --name "1076 2027" writes cad/advantagescope.yaml. Fill in signals, ratios, directions, onshape_url.
  4. … cad2ascope run --zip export.zip, then wire RobotVisualizer and visualizer.set(...) calls; ./gradlew test.
  5. Mentor: copy the workflow, add secrets ONSHAPE_ACCESS_KEY / ONSHAPE_SECRET_KEY and variable ONSHAPE_BASE_URL, allow Actions to write and open pull requests, add cad/drops/.gitkeep, add !cad/drops/*.zip to .gitignore.
  6. Do P2 once to confirm.

P2. Update the model

Any student · whenever CAD changes · ~2 minutes of clicks

Route A: Run workflow

  1. Onshape: Named Position ascope_zero, then create a Version with a clear name (“Week 4, new intake plates”).
  2. GitHub: Actions → Update robot model → Run workflow. Leave blank for the newest Version.
  3. Wait 5 to 15 minutes for the pull request on robot-model/update.
  4. Read the pull request top to bottom:
    • First line says Robot code changes needed? → do P3.
    • Preview images: everything attached and in place?
    • Zero-pose check says Pass?
    • Camera table: anything moved? → vision lead checks it.
    • Warnings.
  5. Ask the software lead or a mentor to review and merge. Nothing merges by itself.

Route B: no API key (drop a zip)

  1. Onshape: AdvantageScope configuration, ascope_zero → Export → URDF, GLTF, Medium → download.
  2. GitHub: new branch → cad/drops/ → Add file → Upload files → one zip → commit.
  3. The workflow replaces the zip with the new model on your branch. The report is on the Actions run page.
  4. Open a pull request from your branch and ask for a review.
Run failed? Open it in Actions, find the red X step, look up the message on the P5 sheet.

P3. Add or remove a mechanism

CAD student + programmer · ~15 minutes
Adding or removing a moving mechanism changes the signals robot code must provide. The build breaks on purpose until the code catches up.
  1. CAD student: add or rename the Revolute/Slider mate j_… with limits. Pose at ascope_zero. Create a Version.
  2. Programmer: in cad/advantagescope.yaml, add (or remove) the joint under joints and its signal under signals. Commit.
  3. Do P2 Route A. Expect the first line “Robot code changes needed” and a failing ./gradlew test.
  4. Programmer: check out robot-model/update. In the subsystem's periodic(), add visualizer.set(Signal.NEW_NAME, position) (meters or radians), or delete the call for a removed signal. Push to the same branch.
  5. Test passes → pull request goes green → review and merge.
Full version: docs/robot-model/P3-add-mechanism.md

P4. View the robot in AdvantageScope

Anyone · team PC, personal device, mentor computer (not district MacBooks)
  1. Pull the latest robot code (or download the repo).
  2. AdvantageScope: App → Use Custom Assets Folder → the repo's assets/advantagescope. Once per computer.
  3. Open a log, or connect to the robot or simulator.
  4. Add a 3D Field tab and pick this season's robot model.
  5. Drag the robot's pose (the Pose2d/Pose3d the drive code logs) onto the field.
  6. Drag RobotModel/Measured onto the robot as components.
  7. Optional ghost: robot pose again as a ghost, with RobotModel/Setpoint as components.
  8. Camera views: pick a cam_ view in the 3D field's camera menu and compare with the PhotonVision stream.
Save your layout so the next person skips steps 4 to 7.

Symptoms

  • Does not move: mate missing j_, not in the config, or on a grounded part.
  • Moves the wrong way: direction: -1. Offset at zero: re-export from ascope_zero or set zero_offset_deg/_m.
  • Comes apart when moving: cut loop; fasten all but one joint. Slow or missing parts: tune mesh.* settings.
  • Camera moved a lot: vision lead checks before merging.
